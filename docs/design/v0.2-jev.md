# Design: Jev integration scope gate (T21.0)

## Problem

cox already reduces several turn points to a narrow judgment, and each one is
currently served by a different mechanism: the router picks a tier by static
config (D5), the bash classifier rates risk with tree-sitter heuristics, the
`tool_search` ranks tools with BM25, compaction and memory fire on token
counters. Each is a hand-tuned proxy for "which of these fixed options fits
this state, and how sure are we". The v0.2 question is narrow: is there one
typed decision call that serves all of them better than the proxies, without
becoming a second model the turn depends on?

## The field

TypeSafe Jev is the first System One model (TypeSafe AI, early access since
Sep 2026; `https://docs.typesafe.ai/llms.txt` is the machine-readable index).
It is not a chat or coding agent and generates no text: state + typed
questions in, type-safe structured answers out, every answer carrying
calibrated per-option probabilities and a confidence score. Three primitives
(`docs.typesafe.ai/primitives`):

- **Choice** — pick one option from a fixed set (≤ 255 options; above that, a
  score-then-choose cascade). Returns the winner, a probability per option,
  and confidence.
- **Score** — rate the state against ordered, descriptive levels. Returns the
  score, a probability per level, and confidence.
- **Noul** — yes/no question; returns P(yes) plus confidence.

Questions in one request are independent and run in parallel (speculative
fan-out: batch 13 questions in one call rather than 13 calls); a second
request exists only when code cannot build it without the first answer. A
complex judgment splits into several questions whose answers code combines
with weights it owns (composite scoring). The documented patterns that map
onto cox call sites: **intent routing** (classify → deterministic logic /
specialist LLM / human), **confidence-gated routing** (the answer says what,
confidence says whether to act), **skill suggestion** (rank 182 skills in one
request, re-read the top three, may reject all), **LLM guardrails** (screen a
message for jailbreak/severity, threshold the probabilities), hierarchical
classification.

Contract: own System One JSON over `POST /v1/systemone` — no OpenAPI.
Python and JS SDKs (`@typesafe-ai/sdk`); LangChain middleware (ModelRouter,
AutoMode) and the Vercel AI Gateway (`typesafe-ai/jev`) for harness use.
Keys via waitlist at `console.typesafe.ai` (`TYPESAFE_API_KEY`). Agent skill
for Claude Code/Codex installs via `claude plugin install typesafe@typesafe-ai`
(or `npx skills add typesafe-ai/skills`) — data-only, the same tier cox
already treats as fail-open. Pricing (vendor claim, Sep 2026): $0.042/MTok
input, output unmetered; 70–500 ms end-to-end.

## cox

Candidate call sites, each already a fixed-option judgment behind a proxy:

| cox site today | proxy | Jev primitive |
| --- | --- | --- |
| router `pick` (D5) | static job→tier table | **Choice** over tiers, confidence-gated: low confidence keeps the static table |
| bash risk class | tree-sitter allowlist (unknown → Exec → ask) | **Score** severity + **Noul** jailbreak screen (guardrails pattern); never lowers a verdict, only raises with reason |
| `tool_search` / skill+command matching | BM25 over name+description | **Choice** over ≤ 5 candidates (skill-suggestion pattern, may reject all) |
| compaction / memory salience | token counters, turn counts | **Score** salience per item; thresholds stay in code, ownable per project |
| hook outcomes | fixed JSON protocol | **Noul** review screen before a `Modify` applies |

Integration type: **type-2 compatible preset first** — Jev arrives as one more
provider behind the existing `Provider` trait (new wire format, same
`stream()` contract), callable only from `cheap`-class jobs, never on the
main-turn path. Type-1 (native wire with first-class request shape) only if
the gate's falsifier (2) fires. The skill (`SKILL.md`) is data-only and can
land independently under the existing `cox-ext` skill rules.

Trust boundary (non-negotiable, mirrors hooks/skills/MCP fail-open): a Jev
answer is untrusted input. It never bypasses `permission::Engine`, never
touches the filesystem or a process except through the traits in
`cox-protocol`, and loses to the local default whenever the key is absent,
the network fails, the latency budget (one cheap call) is exceeded, or
confidence is below the code-owned threshold. The questions and thresholds
live in one reviewable place (config + one code file), per TypeSafe's own
review guidance. No Jev output reaches the terminal except through
`tui::text::sanitize`.

## Falsifiers

1. No call site measures better than its proxy on a recorded cassette
   (same state in, proxy vs Jev out, human grades): drop the site, keep the
   proxy. If none of the five sites beats its proxy, drop the integration.
2. Jev's latency or key requirement breaks the cheap-job contract (offline
   machine, no key, > 500 ms p95 on the five sites): it stays a data-only
   skill, never a provider.
3. The System One wire format churns (early access): pin the contract sketch
   here, not a dependency — the gate fails, implementation waits.

## Review

Gate only: contract sketch above, verified 2026-09-20 against
`docs.typesafe.ai/llms.txt`, `/primitives`, `/agent-skill`, and the Jev
launch post. Implementation (provider wiring, `cheap`-job call sites,
question/threshold file, key handling) is a separate task after this gate —
and needs a `plan.md` §1 row plus the one-line dependency reason per the
no-new-dependency rule.
## Outcome

The gate above led to a built-in provider (T21.1). That is not what shipped in
the end: the integration is the `jev` plugin (`plugins/jev`, A52, T33.40), and
the core no longer contains a Jev client. A decision model is a vendor
integration, so it belongs behind the plugin ABI like any other; the core keeps
only the generic seams it needs.

- The plugin exports the `typesafe` provider and the System One wire
  (T33.40.2–T33.40.4). `cox_decide` can answer with a model call that the host
  runs through the budget gate and the ledger (T33.40.1).
- A legacy `[providers.typesafe]` table now configures the plugin's section
  (T33.40.5) and is read as a tombstone with a one-time migration notice
  (T33.40.14).
- The `risk` advisor can only raise a verdict, never lower it, and asks one
  batched question per tool batch (T33.40.6, T33.40.6.1). The core can offer a
  cache-aware tier downgrade for `route` (T33.40.8).
- The built-in client, its router and `ProviderId` arms, its catalog rows and
  prices, and the `cox-provider-jev` crate split (T32.15, dropped) are gone
  (T33.40.12, T33.40.13, T33.40.15).

The eval verdicts are not in yet. E1 (`risk` against the classifier alone,
T33.40.7) needs a live key and has not run; the `route` advisor (T33.40.9) and
E2 (T33.40.10) are still open. Until E1 reports, this page records no verdict on
whether Jev beats the bash classifier, and the plugin stays opt-in.
