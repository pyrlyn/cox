# Design: Cursor Cloud Agents API scope gate (T49.5)

## Problem

P35 already drives Cursor as a local subprocess (`agent -p --output-format
stream-json` or `agent acp`, `docs/design/external-agents.md`, EA). That run
dies with the laptop: sleep, a closed lid or a dropped session ends it. The
number a cloud run must buy: **hours of background work that continue while
the machine that started them is off**, which the local path covers at
exactly zero. Target, not a measurement: a task started before the lid
closes has a result, an archived transcript and a `usage` row when the
session resumes. If users never start work they expect to outlive the
machine, the number is zero and the gate closes.

## The field

- `research.md` §4.3.8 (checked 2026-09-26): the Cloud Agents API is
  agent-shaped, not chat-shaped — `POST/GET /v1/agents`, runs
  (`POST/GET /v1/agents/{id}/runs`), SSE at
  `…/runs/{runId}/stream`, `POST …/cancel`, `GET /v1/agents/{id}/usage`
  (token counts), artifacts; a Cloud Agent clones a repo and works on its
  own branch. Auth is HTTP Basic (key as username) or Bearer, equivalent, on
  `https://api.cursor.com`; keys from the dashboard.
- Spec: OpenAPI 3.0.3 at
  https://cursor.com/docs-static/cloud-agents-openapi.yaml — HTTP 200,
  59 113 bytes when fetched 2026-09-26 (`research.md` §4.3.8,
  checked 2026-09-26). Endpoint page: https://cursor.com/docs/cloud-agent/api/endpoints.
  **Not re-fetched for this doc**: the card asks for a fresh size and date,
  but this pass made no network call, so today's size is **unverified**; the
  figures above are the 2026-09-26 ones.
- Billing: usage draws on the caller's Cursor plan; third-party models at
  list price plus a $0.25/M-token Cursor rate, Cursor's own models exempt
  from that surcharge (https://cursor.com/help/models-and-usage/token-rate,
  checked 2026-09-26 in §4.3.8, which marks it **med**, not re-verified
  line by line).
- ToS: silent on third-party clients of the Cloud Agents API
  (https://cursor.com/terms-of-service, checked 2026-09-26 in §4.3.8), which
  flags it **for the creator**, unlike Anthropic's written prohibition.
- No Rust SDK exists (§4.3.8); the official SDKs are proprietary TS/Python.

## cox

**Surface.** A run maps onto the task events T34.8 already carries to every
surface: `Event::TaskCreated { task, label, tier }` when the run is created,
`Event::TaskMessage` for a follow-up sent into the run, and
`Event::TaskCompleted { task, result_item, cost_usd, … }` when the SSE
stream ends or `GET …/runs/{runId}` reports a terminal state. The TUI's
`/agents` card, stream-json and ACP (`crates/cox-acp/src/server.rs` already
forwards all three) need nothing new.

**Seam: a host-driven plugin capability, not guest HTTP.** A54 put Cursor
behind plugins, and P35 did it as a host-side capability
(`[[external_agents]]`, the host spawns and maps). The cloud path needs the
same shape — a new manifest capability the host drives — because the
guest's `cox_http` does not fit: it is request/response with a body cap, so
it cannot hold an SSE stream open for hours; the key would have to enter
wasm memory (host-side key injection exists only for `[[provider]]`
sections, `docs/design/plugins.md` §7a); and PL§7d already rules that raw
`cox_http` to a paid API bypasses the ledger. The grant line names the
network host and the key env (`CURSOR_API_KEY`, resolved like any provider
key, never from tests' real keychain), as P33/P35 grants do.

**Code leaves the machine.** A Cloud Agent clones the repository from its
GitHub remote and pushes a branch; cox's sandbox cannot confine a process on
Cursor's servers. So the approval is `cox_permission::Engine`'s, raised as
an `ApprovalRequired` whose text says the repository, the remote and that
the code is read and edited off this machine — never a plugin-side check,
and never auto-allowed by `auto` mode. `cox_sandbox::sandbox::Policy` and
`cox_sandbox::path::confine` do not apply to the remote run and are not
weakened: nothing runs locally. Every line from the SSE stream and every
artifact name passes `cox_sanitize::sanitize` (D14).

**Ledger.** Each run's `GET /v1/agents/{id}/usage` becomes a `usage` row
(model, input, output, cache read and write when reported) when the run
ends, or the feature does not ship. The price: EA§6's rule applies —
`billed_externally: true` and never an estimated USD for spend that lands on
the user's Cursor plan; `cost_usd` on `TaskCompleted` is then $0 with the
tokens recorded.

**Types.** From the OpenAPI spec per A40 step (2) (typify, or `progenitor`
for 3.0.3 per R§4.3.1), vendored only by a `scripts/vendor` script (A48),
with the redistribution question §4.3.8 raises about a spec with no license
grant answered first.

## Falsifiers

1. Usage cannot be priced into the ledger — `…/usage` lacks the fields a
   `usage` row needs, or does not attribute tokens to a model — then the
   rule "a cost that is not a `usage` row does not exist" blocks it.
2. The ToS question resolves against third-party clients — then reject.
3. Runs require a repository host cox cannot assume (GitHub only, through
   Cursor's GitHub App) — then it serves only GitHub-hosted repos with the
   app installed, and the problem number shrinks to that share.
4. Users do not start work they expect to outlive the machine — the problem
   number is zero.

## Review

**Recommended verdict: defer** — pending the creator's decision, and
blocked on two answers only the creator can give: the ToS reading for a
third-party client (§4.3.8), and whether a `billed_externally` row with
Cursor-reported tokens satisfies the ledger rule for this path as EA§6 lets
it for the local CLI. If both answers are yes and the creator chooses
**build**, the §6 amendment draft is: (1) a `scripts/vendor` script for the
OpenAPI file (license question noted); (2) the manifest capability and its
grant line; (3) a host driver mapping create/stream/cancel/usage to the
task events and the ledger; (4) the `Engine` approval text for off-machine
code; (5) an offline e2e over recorded SSE fixtures, no live key (D12).

**Creator's verdict (2026-09-29, `plan.md` A123): build** as described above, cards T56.1–T56.10. A terms check the same day (A123 (5)) found that Cursor's Acceptable Use Policy prohibits automated or non-human access and that the OpenAPI file carries no licence while the Terms forbid reproducing the Documentation: the spec is not vendored and the wire types are hand-written from the public docs, and the creator's written go-ahead on third-party API access came on 2026-10-03 (the T56.3 and T56.5 cards cite it), and the P56 cards followed.

**Status: built, with the deviations below.** The cards are T56.1–T56.8 in
[`done.md`](../../done.md); T56.9 is the docs, and T56.10–T56.12 are open.
The user-facing reference is the "Cloud agents" section of
[`docs/plugins.md`](../plugins.md); the local path's design, which the cloud
driver shares the dispatch with, is [`external-agents.md`](external-agents.md) §9.

- Approval: an `ApprovalRequired` prompt is not raised. A background task has
  no route to the prompt, so `Engine`'s `Ask` is refused with the approval text
  and the `CloudAgent(<owner>/<repo>)` rule to add (T56.6). The rule is the
  lift.
- Follow-ups: the `TaskMessage` path is not built. The client has `create_run`;
  no driver calls it.
- Resume: a run left by a closed session is followed or finalized on resume;
  one reattached after a resume cannot be cancelled (T56.7).
- Tests: offline over hand-written fixtures (T56.8). The live check against a
  real account is T56.10 and needs the creator's key.
