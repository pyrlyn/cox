# Localization (i18n)

cox keeps its user-facing strings in GNU gettext catalogs: one template,
`messages.pot`, and one `.po` file per language. The Rust side embeds the
`.po` files and reads them at runtime through `gettext-catalog` (pure
Rust, no libintl, so nothing extra on macOS or Windows); the native desktop
apps get the same strings as
platform resource files generated by `po-export`. The catalogs are the single
source of truth: never edit a generated `.strings`, `.stringsdict` or `.resw`
file.

Status: groundwork. The crate, the catalogs and the export exist; no surface
(TUI, CLI, macOS app) reads from them yet.

## Languages

| Code | Language | gettext forms (`msgstr[i]`) | CLDR categories | Role |
| --- | --- | --- | --- | --- |
| `en` | English | 2: `[0]` one, `[1]` other | `one`, `other` | source, default and fallback |
| `ru` | Russian | 3: `[0]` one, `[1]` few, `[2]` many | `one`, `few`, `many`, `other` | translation |
| `uk` | Ukrainian | 3: `[0]` one, `[1]` few, `[2]` many | `one`, `few`, `many`, `other` | translation |

`Plural-Forms` headers (tests check them verbatim):

```
en:     nplurals=2; plural=(n != 1);
ru, uk: nplurals=3; plural=(n%10==1 && n%100!=11 ? 0 : n%10>=2 && n%10<=4 && (n%100<10 || n%100>=20) ? 1 : 2);
```

Codes are BCP 47 language subtags, the same in the file name, negotiation
and the Apple `<code>.lproj`; Windows folders add the region (`en-US`,
`ru-RU`, `uk-UA`).

## Layout

```
crates/cox-i18n/
  po/README.md            the catalog workflow, short
  po/messages.pot         the template: every message, English, no translations
  po/en.po                English: msgstr repeats the msgid
  po/ru.po
  po/uk.po
  src/lib.rs              embedding, `{brand}`, the process-wide localizer, t() and tr!
  src/export.rs           .po -> .strings / .stringsdict / .resw
  src/bin/po-export.rs    the export command
```

Parsing, `Plural-Forms`, `{name}` placeholders and the localizer are
`gettext-catalog` 0.1.0, re-exported as `catalog`, `plural` and `format`.

The `.po` files are embedded with `include_str!` and parsed on first use, so
the binary needs no files at runtime and there is no build step (no `.mo`).
They live inside the crate so it stays self-contained.

## Conventions

- **Ids are `msgctxt`.** Every message has a stable id in `msgctxt`
  (`session-count`); the `msgid` is the English source text. Code passes the
  id (`tr!("session-count", …)`), so rewording English changes only the
  `msgid`, and `msgmerge` marks each translation `fuzzy` for review, which is
  gettext's normal stale-translation flow. An entry without `msgctxt` is
  looked up by its `msgid`.
- **Named placeholders.** gettext has no named arguments, so cox uses
  Python's brace syntax, which gettext calls `python-brace-format`: `{name}`
  (an ASCII identifier), with `{{` and `}}` for literal braces. Entries with
  placeholders carry `#, python-brace-format`, so `msgfmt --check` verifies
  that every translation uses the msgid's placeholders. `{0}` and
  `{name:>4}` are not placeholders; the tests and the export reject them.
- **The product name** (the Fluent term `-brand-name`) is the placeholder
  `{brand}`, filled with `cox_i18n::BRAND_NAME` (`Cox`) at runtime and
  inlined as text by the export. A caller may pass `brand` to override it.
- **Plurals** are `msgid`/`msgid_plural` entries with one `msgstr[i]` per
  form of the locale's `Plural-Forms`. The form is selected by the argument
  named `count` (the placeholder `{count}`, which every plural message must
  use).
- **Comments.** `#.` (extracted comments) in the template describe each
  placeholder (`#. {count} (number): …`); they reach the exports.

## Adding or changing a string

1. Edit [`po/messages.pot`](../crates/cox-i18n/po/messages.pot): add the
   entry with its `msgctxt` id, English `msgid` (and `msgid_plural`),
   `#, python-brace-format` if it has placeholders, and a `#.` comment for
   each placeholder. Leave the `msgstr` lines empty.
2. Run `just i18n-update` (`msgmerge --update` for each `.po`). New entries
   appear untranslated; entries whose English changed become `fuzzy`.
3. Fill in `en.po` (msgstr = the English text) and translate `ru.po` and
   `uk.po`; clear the `fuzzy` flag once a translation is reviewed. A missing,
   empty or fuzzy translation is not an error: the message resolves from `en`
   (see below), and the export fills it in.
4. Plurals, Russian:

   ```po
   #. {count} (number): open sessions in the sidebar.
   #, python-brace-format
   msgctxt "session-count"
   msgid "{count} session"
   msgid_plural "{count} sessions"
   msgstr[0] "{count} сессия"
   msgstr[1] "{count} сессии"
   msgstr[2] "{count} сессий"
   ```

5. Run `just i18n-check` (`msgfmt --check` and `msgcmp`, needs
   `brew install gettext`) and `cargo test -p cox-i18n`: it parses every
   catalog, checks the `Plural-Forms` headers, that each `.po` holds exactly
   the template's messages, that no translation uses a placeholder the English
   lacks, the plural forms, and it runs `msgfmt --check` when gettext is
   installed.

## Adding a locale

1. `msginit --input=crates/cox-i18n/po/messages.pot --locale=<code>
   --no-translator --output-file=crates/cox-i18n/po/<code>.po`, where
   `<code>` is the language subtag (`de`, `pl`). msginit writes the
   standard `Plural-Forms` for the language; check it against the GNU
   gettext manual ("Plural forms"). Replace the template's file comment with
   one naming the language and its forms.
2. Translate. Untranslated entries resolve from `en`.
3. Register it in `LOCALES` in `crates/cox-i18n/src/lib.rs`: the code, its
   `include_str!`, the Windows folder (`de-DE`), `plural_categories` (the
   CLDR category of each gettext form, in `msgstr` index order) and
   `other_form` (see "Fractions" below).
4. Extend the `msgfmt`/`plural_categories` tests if the language has a new
   rule shape, then run `just i18n-check` and `cargo test -p cox-i18n`.

## Rust usage

```rust
use cox_i18n::{tr, t, Args, Localizer};

// Process-wide, negotiated from the env and OS on first use.
let title = tr!("settings-title");
let count = tr!("session-count", count = 5);
let welcome = tr!("welcome-user", name = "Ivan");

// Or explicitly, e.g. in tests or for a per-session language.
let uk = Localizer::for_tags(&["uk-UA"])?;
let mut args = Args::new();
args.set("count", 21);
assert_eq!(uk.format("session-count", Some(&args)), "21 сесія");
```

The API is the Fluent version's with `FluentArgs`/`FluentValue` renamed to
`Args`/`Value` (`Value::Str`, `Int`, `Float`, with `From` for strings and
numbers).

- **Negotiation.** The requested languages are the POSIX message locale
  (`LC_ALL`, then `LC_MESSAGES`, then `LANG`; `uk_UA.UTF-8` is understood,
  `C`/`POSIX` are ignored) followed by the OS UI languages (`sys-locale`; a
  GUI app has no `LANG`). They are matched by language subtag against `en`,
  `ru` and `uk`, in request order, so `uk-UA` selects `uk`. `en` always ends
  the chain.
- **Per-message fallback.** A `Localizer` holds one catalog per locale in the
  chain, for example `[uk, en]`. Formatting walks the chain and uses the first
  catalog with a usable translation: not missing, not `fuzzy`, and every
  `msgstr` non-empty (a plural with one empty form falls back as a whole).
  After `en`'s `msgstr` comes the English `msgid` (`msgid_plural` for any
  count but 1), so an empty `en.po` entry still shows English.
- **Missing keys.** An id no catalog defines renders as the id itself
  (`format`), so it is visible in the UI; `try_format` returns `None`. A
  placeholder without an argument stays spelled `{name}`.
- **Counts.** Pass `count` as a number (`count = 5`, not `"5"`). Integers
  select through `Plural-Forms` (negative counts by their absolute value,
  since gettext counts are unsigned). A fraction, a string or a missing
  `count` selects CLDR `other`, as a Fluent select did.

## Plurals and fractions

gettext forms are positional: `msgstr[i]` is whatever `Plural-Forms` returns
for an unsigned integer `n`. CLDR names categories instead, and Russian and
Ukrainian have one gettext has no form for: `other`, used only for fractions
(1.5). The mapping, used by the runtime and the export alike:

| Locale | `[0]` | `[1]` | `[2]` | CLDR `other` |
| --- | --- | --- | --- | --- |
| `en` | one | other | | `[1]` |
| `ru`, `uk` | one | few | many | `# cldr-other:` override, else `[1]` (few) |

The few form is the genitive singular in Russian (`1,5 файла`), which is what
fractions take, so `ru` needs no override. In Ukrainian the few form is the
nominative plural (`файли`) while fractions take the genitive singular
(`файлу`), so `uk.po` gives it in a translator comment, which `msgmerge`
preserves:

```po
# cldr-other: {name} змінює {count} файлу
msgctxt "files-changed"
```

## Native export

```
cargo run -p cox-i18n --bin po-export            # writes target/i18n/  (just i18n-export)
cargo run -p cox-i18n --bin po-export -- --out <dir>
```

Output (under `target/`, gitignored; never commit it):

```
target/i18n/apple/{en,ru,uk}.lproj/Localizable.strings
target/i18n/apple/{en,ru,uk}.lproj/Localizable.stringsdict
target/i18n/windows/Strings/{en-US,ru-RU,uk-UA}/Resources.resw
```

Messages a translation lacks (missing, empty or fuzzy) are written into its
files from `en` (marked `fallback: en` in the comment), because neither
Foundation nor the Windows resource loader falls back per key the way the
Rust side does.

### macOS: `.strings` + `.stringsdict`

Plain messages go to `Localizable.strings`, plural messages to
`Localizable.stringsdict`. Why not a String Catalog (`.xcstrings`): a catalog
is an editable source that Xcode rewrites on every build (string extraction,
state tracking), which fights a generator that owns the file; the app has no
catalog or `.lproj` yet; and the legacy pair is per-language, plain, and
checkable with `plutil -lint`. Foundation still reads them on macOS 26.

Mapping:

- `msgctxt` id -> key, unchanged (`String(localized: "session-count")`).
- `{name}` -> `%@`; `{count}` in a plural message -> `%lld`. With two or more
  placeholders, specifiers are positional (`%1$@ … %2$lld`), numbered by
  first appearance in the `en` message, so a translation may reorder them.
- `{brand}` is inlined as `Cox`; a literal `%` becomes `%%`, `{{` becomes `{`.
- A plural message becomes `NSStringLocalizedFormatKey = "%#@count@"`
  (`%2$#@count@` when `count` is the second argument) with one complete
  string per CLDR category: the gettext forms by `plural_categories`, plus
  `other` as in the table above. English fallbacks carry `one`/`other`.

```xml
<key>files-changed</key>
<dict>
  <key>NSStringLocalizedFormatKey</key>
  <string>%2$#@count@</string>
  <key>count</key>
  <dict>
    <key>NSStringFormatSpecTypeKey</key>
    <string>NSStringPluralRuleType</string>
    <key>NSStringFormatValueTypeKey</key>
    <string>lld</string>
    <key>one</key>
    <string>%1$@ змінює %2$lld файл</string>
    <key>few</key>
    <string>%1$@ змінює %2$lld файли</string>
    <key>many</key>
    <string>%1$@ змінює %2$lld файлів</string>
    <key>other</key>
    <string>%1$@ змінює %2$lld файлу</string>
  </dict>
</dict>
```

Hooking it into the build: `scripts/desktop/app.sh` should run
`cargo run -p cox-i18n --bin po-export -- --out desktop/macos/build/i18n`
before `xcodegen generate`, and `desktop/macos/project.yml` should list
`build/i18n/apple` as a resource folder of the `Cox` target (XcodeGen turns
each `<code>.lproj` into a variant group; `CFBundleDevelopmentRegion` is
already `en`). A pre-build script phase would also work, but running it in
`app.sh` keeps Xcode free of a cargo dependency. Not wired yet.

### Windows: `.resw`

One `Strings/<tag>/Resources.resw` per locale, the layout a WinUI 3 project
(`desktop/windows/`, planned in P58) picks up with `ResourceLoader`.

- `{name}` -> `{0}`, `{1}`, … in `en` first-appearance order, for
  `string.Format`; literal braces are doubled.
- **Plurals: `.resw` has none.** A plural message becomes one entry per CLDR
  category, `session-count_one`, `session-count_few`, `session-count_many`,
  `session-count_other` (`_one`/`_other` for English). The app picks the
  category for the number with ICU's plural rules (Windows ships ICU,
  `icu.dll`) and falls back to `_other` when an entry is missing.
- Hooking it into the build: an MSBuild `BeforeBuild` target runs the export
  into the project's `Strings/` folder (or copies from `target/i18n/windows`).

### What the export rejects

A translation whose id is not in `en`, a placeholder the `en` message does
not have, a brace that is neither `{name}` nor doubled, a plural message
without `{count}`, a plural translation whose number of forms differs from its
`Plural-Forms`, and a `Plural-Forms` whose `nplurals` does not match the
locale's `plural_categories`.

## Compared with Fluent

The crate used Fluent (`.ftl`, `fluent-bundle`) until this port. What changed:

- **Tooling.** gettext is what translators and platforms (Weblate, Crowdin,
  Poedit, Launchpad) already speak; `msgmerge` flags stale translations as
  fuzzy, and `msgfmt --check` validates headers, plural counts and
  placeholders.
- **No selectors beyond plurals.** Fluent's `select` on strings (gender,
  platform) and nested selects have no gettext form; each variant becomes its
  own message id chosen by the caller.
- **Positional plurals.** Forms are `msgstr[0..n]`, and their meaning lives in
  the `Plural-Forms` expression, not in named categories; CLDR `other` for
  fractions needs the convention above.
- **One number per message.** Only `count` selects; Fluent could select on any
  variable, or on several.
- **No terms or message references.** `{brand}` is a substitution the crate
  performs; other shared text is duplicated or passed as an argument.
- **Formatting.** No `NUMBER()`/`DATETIME()`: arguments are rendered with
  Rust's `Display`, so locale-aware number formatting is the caller's job.
- **Bidi isolation.** Fluent wrapped placeables in FSI/PDI (cox turned it
  off); gettext never does.
